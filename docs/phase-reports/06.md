## Bugs found by verification (fixed, not waived)

1. **`rootHreflangs` broke ID-page alternates** (`src/lib/archive.ts`): prefixed canonicals produced `/id/id/...` hrefs. Fixed by stripping the locale prefix first; all static-page pairs now symmetric. Pre-existing Phase-3 bug, fixed within step-3 scope.
2. **D1 rejects aliased FTS tables** (`no such column: f`): `FROM posts_fts f ... WHERE f MATCH` fails on D1's SQLite — unaliased `posts_fts MATCH` with the `posts` table unaliased works (probe passed unaliased).
3. **drizzle-kit `generate` TTY prompt**: my first schema edit accidentally deleted `createdAt/updatedAt` (range-replace overrun) → created+deleted column conflict → interactive prompt that cannot run headless. Restored the columns; clean `ALTER TABLE ... ADD og_image_key` generated.
4. **Admin e2e CSRF**: API `POST/PUT/DELETE` from Playwright `request` needs `Origin: http://localhost:4322` + JSON body (DELETE needs `data: {}` for the Content-Type). Same lesson as Phase 5's multipart guard, HTTP-client edition.
5. **Reading-spec drift**: RSS autodiscovery doubled `hreflang="id"` links (scoped to `:not([type])`); post `script` count 2 → 3 (JSON-LD block joins the two inline scripts).

## Deviations / notes

- FTS5 lives outside `drizzle-kit` (virtual tables unmodellable): custom migration `0002_posts-fts.sql` + raw `sql`-template access with bound params only. `tests/setup.ts` now applies **all** `migrations/*.sql` via eager glob (was hardcoded to `0000`).
